# 前滚翻的训练与成功定义

`Mjlab-ForwardRoll-Flat-MicroDuck` 继承官方 `Roulade`。动作是接地前滚翻：低头、蹬腿、头顶支撑、身体沿前向转动、收腿再伸腿站起。不会提供预先编好的关节轨迹。

## 学习问题

- 每个控制步输出 14 个舵机关节的位置偏移，使用官方 BAM XL330 力矩/摩擦模型。
- Actor 61D 观测按顺序为：角速度 3、投影重力 3、关节位置 14、关节速度 14、上一步动作 14、速度命令 3、头命令占位 4、身体命令占位 6。
- 单次动作最长 5 秒；不因身体倒置或头部触地而提前终止。
- 主奖励使用接地状态下的前向旋转增量，保持不动不能反复获得进度奖励。
- 身体侧向轴偏出水平面时减少旋转计分，侧肩滚动无法替代正向滚动。
- 落地奖励要求先积累旋转，并有头顶朝下的头部接地记录。
- 附加代价处理冲击、过快旋转和抖动；不使用全程直立奖励来压制翻滚探索。
- 训练保留反向课程：部分环境从翻滚中途开始学后半程，逐步提高站立起步占比。课程按每次 PPO 24 步计数，3000 / 6000 次更新切换起步比例。因此默认完整预算为 10000 次更新，训练耗时取决于 GPU。

## 本项目新增部分

训练奖励不做未经验证的重新调权。新增独立实验名、默认 TensorBoard、左右脚独立接触传感器；`play=True` 强制站立起步且清空课程，避免课程覆盖评估设置。训练与评估都保留相同 61D / 14D 接口。

数值保护对齐官方行走任务：监测非有限接触力，并清理 critic 中的接触力和空中时长观测，以避免一次异常接触污染 PPO 参数。

固定版本 tyro 1.0.5 无法解析官方对称损失配置的 `dict | None` 默认值。本项目将该程序配置从命令行参数中隐藏，保留 PPO 中的对称损失功能，防止训练命令在启动前报错。

评估每个环境只观察一个 5 秒窗口。到窗口末尾，以下条件连续保持至少 0.5 秒才记成功：

1. 接地前向累计转动至少 330°；它是由角速度积分得到的任务代理量，存在积分误差，不代表精确测量一整圈。
2. 获得官方头顶接地 latch；站立评估不预置 latch。
3. 躯干高度在 0.115 ± 0.025 米，倾角不超过 20°。
4. 左右脚都接地，角速度范数不超过 1 rad/s。
5. 全程没有非有限状态或提前复位。

该成功率使用官方接触/旋转判据，仍需配合视频检查；不是对接触点和运动路径的独立几何证明。报告同时包含头顶接触率、逐环境转动量、末尾稳定时长、最终高度和倾角，便于辨别“翻过去但站不起来”和“根本没开始翻”。

负对照：

```bash
uv run python scripts/evaluate_forward_roll.py --agent zero --num-envs 64
```

零动作应该接近 0% 成功；若成功率异常，应先排查指标和起步状态，再判断策略好坏。至少用三组 seed 重复评估，分别查看成功率和视频。不要只根据总 reward 选择最佳模型。

## 调整训练时看什么

TensorBoard 中观察 `Episode_Reward/roulade_progress`、`roulade_landing_composite`、`roulade_landing_sharp` 和 episode length。惩罚项的加权记录应为非正值。总奖励增长但旋转进度不增长通常意味着技能尚未学到。

先检查实际模型、复位姿态和评估视频，再修改奖励。保留固定版本的基线，每次更改只改变少量参数，使用独立 run name 保存。恢复同任务检查点是续训；从其他技能检查点开始属于 warm start，课程与归一化需另行处理，不建议第一轮尝试。

## 云端常见问题

- `torch.cuda.is_available() == False`：确认实例分配了 GPU、驱动可用且安装 CUDA 版 Torch。不要将依赖随意换为最新版本；先使用 `uv sync --frozen`。
- 显存不足：从 64/256/1024 逐级增加环境数。头部与身体碰撞使翻滚比仅足部接触的行走更昂贵。
- EGL / OpenGL 错误：先关闭视频完成训练。需要视频时使用平台支持的带 EGL NVIDIA 镜像，检查显卡容器设备和图形库。
- SSH 中断：使用平台作业功能或 tmux，在持久化目录训练。
- 续训会保留优化器、归一化和课程计数，并生成新的运行目录；`--iterations` 是此次追加更新次数。
- GitHub 只保存源码和固定模型，训练结果另行保存。不要提交云端 Token、W&B/HF 凭据或大检查点。
